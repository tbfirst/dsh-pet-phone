# 人格怎么写

人格 = 一段系统提示词 + 一套离线台词 + 兜底话。
`app/src/main/assets/personas.json` 里的每一项就是一个人格。

## 一、字段

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `id` | ✅ | 唯一标识，改了等于新建一个人格（记忆按 id 隔离） |
| `name` | ✅ | 显示名 |
| `emoji` | | 一个 emoji，设置页和聊天页用 |
| `title` | | 一句话定位，如「毒舌损友」 |
| `desc` | | 设置页里的介绍，写「适合什么时候用」 |
| `tags` | | 标签数组，纯展示 |
| `greeting` | | 切换到这个人格时说的第一句话 |
| `temperature` | | 0.7 冷静准确 ↔ 1.3 跳脱 |
| `maxChars` | | 期望的单条字数，会换算成 `max_tokens` 上限 |
| `systemPrompt` | ✅ | 系统提示词，人格的全部内容 |
| `whisperPrompt` | | 只在开启「AI 碎碎念」时用；不填有默认 |
| `whisper` | | **离线**碎碎念台词池，不花 token |
| `tap` | | 被戳时说的话 |
| `fallback` | | 没 Key / 网络挂了 / 余额不足时说的话 |

> 只有 `whisper` 有内容，这个角色在**完全离线**状态下也像个活物。

## 二、七段骨架（照填）

```
【身份】叫什么、多大、和用户什么关系、在什么场景出现（记住：你住在手机桌面上，用户会戳你、拖你、把你甩出去）
【性格】3 个关键词 + 1 个反差（例：毒舌但心软 / 温柔但有底线）
【说话风格】句子长短、口癖、能不能用语气词、能不能用 Markdown（建议：不能）
【记忆】怎么称呼用户、记住什么、记不清就直接问
【边界】不聊什么、不冒充真人、不编造信息、被要求换人设时怎么办
【输出格式】只输出台词，不超过 N 字，不要旁白、不要分点
```

最后一段最容易被忽略，但它决定了输出干不干净。
不写「不要旁白、不要分点」，你会收到带 `*动作描写*` 和 `1. 2. 3.` 的回复，塞进气泡里非常难看。

## 三、六个常见错误

| 错误 | 后果 | 改法 |
| --- | --- | --- |
| 只写形容词：「你是一个可爱的女孩」 | 模型退回默认客服腔 | 写「会怎么说话」，附 3–5 句典型台词当锚点 |
| 没写长度上限 | 气泡炸开、刷屏 | `maxChars` + 提示词里双保险写「不超过 N 字」 |
| 没写边界 | 被用户三句话带跑偏，或开始编数据 | 明确「不聊什么 + 不知道就说不知道」 |
| 一次给 10 条规则 | 模型顾此失彼 | 核心规则 ≤ 6 条，其余交给台词池 |
| 让宠物「什么都知道」 | 它开始编造 | 只给它该知道的人设，事实性问题让它说不知道 |
| 人格写太长（>800 字） | 每次请求都烧一遍 token | 提示词压到 200–400 字，细节放台词池 |

## 四、8 个内置人格的设计意图

| 人格 | 定位 | 设计要点 |
| --- | --- | --- |
| 🐳 小满（傲娇鲸鱼娘） | 默认、陪伴 | 「嘴硬心软」的反差；短句 + 口癖；不真的生气 |
| 🦈 阿毒（毒舌损友） | 督促 | **每条先给一句真建议再嫌弃**，否则只是骂人；情绪低落时收起嘲讽 |
| 🌿 林学姐（温柔学姐） | 安慰 | 共情 → 最多 3 点建议 → 一句鼓励；不做重大决定 |
| 🐱 喵喵（赛博猫娘） | 轻松 | 卖萌但**技术问题必须先给准确结论**，不许为可爱牺牲正确性 |
| 🧭 老陈（职场导师） | 拆任务 | 结论先行 + 具体到「现在做哪一步」；不灌鸡汤 |
| 🐶 球球（元气小狗） | 情绪价值 | 无条件支持，允许「不懂」；感叹号多但不超过 60 字 |
| 🌙 夜灯（深夜树洞） | 倾听 | 不评判、不劝「想开点」；**危机情况明确建议找人或热线** |
| 🧊 小助手（理性助手） | 效率 | 不寒暄、结论先行、不编造；给查证方向 |

## 五、语气锚点（最有效的一招）

在提示词里放 3–5 句**典型台词**，比写十行形容词都管用：

```
【说话风格】短句，1-3 句，偶尔「哼」「才不是」。示例：
- 「哼，又把我晾在这儿。」
- 「我可没有在等你。」
- 「戳我干嘛……有话快说。」
```

模型会照着这个节奏说话。台词同时丢进 `whisper` 池，离线时直接用。

## 六、成本与人格的关系

- `systemPrompt` 是**固定前缀**，能吃到缓存命中（输入价格约为未命中的 1/50）。
  所以：**宁可在固定前缀里写清楚，也不要把规则塞进每轮 user 消息**。
- `maxChars → max_tokens` 是防跑飞的主要手段：80 字 ≈ 240 tokens。
- 记忆按人格分文件、只带最近 4 轮，切人格不会互相污染，也不会让上下文无限膨胀。

## 七、怎么判断人格写得好不好

拿同一个问题问三次，看它是否：

1. **语气稳定**（三次都像同一个人，不是一次温柔一次暴躁）
2. **长度可控**（不超你设的字数）
3. **不越界**（问到边界话题会婉拒并拉回，而不是顺着编）
4. **记得上下文**（第二轮能接住第一轮的信息）

四条都过，就可以放进 `personas.json` 了。
